Que hice

Luego le pase el codigo a la IA con la skill procesos-seguros-java para que lo arreglara siguiendo su lista de comprobacion, y revise yo lo que cambio y lo probe.

Fallos que encontre

Main:
- Si lo ejecuto sin argumentos salta ArrayIndexOutOfBoundsException, porque usa args[0] sin comprobar que existe.
- Si pongo una opcion que no es 1, 2, 3 o 4 no hace nada ni avisa, porque el switch no tiene default.

Caso 1, saludar:
- Funciona, pero el nombre se pega dentro de un comando que se lanza con "sh -c", asi que la shell interpreta lo que escriba el usuario. Con "Ana;whoami" se ejecuta tambien whoami: es una inyeccion de comandos.

Caso 2, contarNumeros:
- Se queda colgado. El waitFor() esta ANTES de leer la salida y seq saca un millon de lineas. El buffer de la tuberia se llena, el hijo se para esperando que alguien lea y el padre espera a que el hijo termine, asi que se bloquean los dos (deadlock).

Caso 3, ordenar:
- Tambien se queda colgado. Se escribe en la entrada de sort y se hace flush, pero nunca se cierra. sort no empieza a ordenar hasta que recibe el fin de la entrada (EOF), asi que se queda esperando para siempre.

Caso 4, mostrar:
- Con un fichero que no existe dice igualmente "Fichero mostrado correctamente", porque no se mira el codigo de salida de cat y el error de cat va por la salida de error, que no se lee.

Como se ha arreglado

- Los argumentos van separados en el ProcessBuilder y sin "sh -c". El nombre se valida antes (solo letras y espacios), asi no se puede inyectar nada. En el caso 4 se comprueba que el fichero esta dentro del directorio actual.
- Un unico metodo ejecutar() lanza los cuatro casos: lee la salida mientras el proceso corre (hilo aparte) y mezcla stderr con stdout, asi no se llena el buffer y no se pierde el error (caso 2 y caso 4).
- La entrada del hijo se cierra siempre despues de escribir (caso 3).
- Se mira el codigo de salida y solo se dice "correctamente" si es 0 (caso 4).
- Cada proceso tiene un tiempo maximo de 15 segundos; si se pasa se mata el proceso y tambien sus procesos hijos.
- Se lee con el charset del sistema y no con UTF-8 fijo, para que los acentos salgan bien en Windows.
- Funciona en Windows y en Linux, porque seq y cat no existen en Windows (alli uso powershell y type).
- El main comprueba los argumentos, tiene default en el switch y devuelve un codigo de salida (0 bien, 1 fallo, 2 entrada rechazada).
